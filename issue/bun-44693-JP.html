タイトルとテンプレートの欄

タイトル

Windows: bun が起動時にコンソールのコードページを 65001 に切り替え、出力を化けさせ、同じ窓のほかのプロセスを壊す（#43660 の根本原因）

bun の版（What version of Bun is running?）

1.4.2+744846f84（1.4.3-canary.1+bbdc5a519 でも再現）

環境（What platform is your computer?）

Microsoft Windows NT 10.0.26300.0 x64

再現手順（What steps can reproduce the bug?）

bun は起動時にコンソールの入力・出力コードページを控えて両方 65001 にし、終了時に控えた値へ戻す（ソースの `init()` と `restore()` へのリンク）。コードページはコンソールに属し、つながる全プロセスで共有されるため、1 つの窓で 2 本の bun が動くと、互いの控えを上書きしてしまう。これが #43660 の根本原因。

**新しい `cmd.exe` の窓**（65001 以外ならどのコードページでもよい。英語版 Windows は 437、日本語版は 932）を開き、次を流す:

（英語版と同じコマンド）

`ping` とタイマーは順番を決めるためだけのもの。送り手が先に起動し、受け手が約 1 秒後に起動し、受け手が動いているあいだに送り手が終わる。毎回再現した（437 で 3 回中 3 回、932 で 3 回中 3 回。両方の版）。

期待する動き（What is the expected behavior?）

文字列が正しく出て、窓のコードページは変わらない。両方の `bun -e` を `node -e` にしたときの出力（`deno eval` にしても同じ）:

abc 東京大阪 xyz
Active code page: 437

実際（What do you see instead?）

437 の窓:

932 の窓（日本語版 Windows）:

abc 譚ｱ莠ｬ螟ｧ髦ｪ xyz
Active code page: 65001

起きていること:

1. 送り手が起動し、437 を控えて 65001 にする
2. 受け手が起動し、65001 を「元の値」として控える
3. 送り手が終わり、437 に戻す
4. 受け手が、437 になった窓へ UTF-8 のバイト列をそのまま書くので化ける
5. 受け手が終わり、65001 に戻す。2 本とも終わったあとも 65001 が窓に残る

補足（Additional information）

**依頼: コンソールのコードページを一切変えないでほしい。** 画面への出力は `WriteConsoleW`（UTF-8 → UTF-16）、パイプ・ファイルへはバイト列をそのまま、コンソールからの入力は `ReadConsoleW` で読む。どれもコードページに依存しない。node と deno は一度も変えず、下のすべてのケースで正しく出す。GitHub のコード検索では、リポジトリに `WriteConsoleW` の使用は見つからない。

控えて戻すやり方は安全にできない。1 つの窓で複数のプロセスが同じ共有の値を控えては戻すので、終わる順で何が残るかが決まる。強制終了では戻す処理そのものが走らない（ソースのコメントにも「強制終了されると戻らないことがある」と書かれている）。ソースへのリンクはいまの `main` を指す。

**測った害**（Windows 11 10.0.26300、conhost、開始のコードページ 932 と 437 の窓、bun 1.4.2 と canary。比べる相手は node v26.10.0 と deno 2.9.7。各プロセスが自分で `GetConsoleCP` / `GetConsoleOutputCP` を読み、画面は `ReadConsoleOutputCharacterW` で読み取った）。node と deno ではどれも起きず、順番を決めたケースの判定は 932 と 437 ですべて同じだった。

1. **パイプでつないだ相手の出力が化ける**（#43660 の症状）。bun 同士が直接つながっていなくても起きる（`bun | node | bun`）
2. **回ごとに結果が変わる。** #43660 のコマンドを毎回新しい窓で 10 回流すと、932 では 1.4.2 が 6 回、canary が 7 回、437 では 3 回と 9 回化けた。回数も流すたびに変わる。node と deno は毎回正しかった。起動・終了の順を決めると、どの順も 3 回中 3 回同じ結果になった
3. **窓に 65001 が残る。** 通常終了でも順番によって残り、強制終了（`taskkill /F`）でも残る
4. **65001 が残ると、同じ窓のほかのプログラムが壊れる。** `cmd.exe` が SJIS のバッチファイルの残りを読み違え（日本語の行が `�������` になる）、`chcp` や `pause` のメッセージが英語になる
5. **パイプのデータそのものは壊れない。** 害はすべて、共有されたコンソールの状態を変えることから起きている

bun#43660 へのコメント

続報: ここで報告した文字化けは、もっと広い問題の症状の 1 つだった。bun は起動時にコンソールのコードページを控えて変え、終了時に戻すが、コードページは窓の全プロセスで共有されるため、同時に動く bun 同士が互いの控えを上書きする。

順番を決めた再現（英語版 Windows の 437 でも再現する）と、node ・ deno と比べた実測を #{NEW} に出した。bun がコードページを変えなくなれば、この Issue も解消する。

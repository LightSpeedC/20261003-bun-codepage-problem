補足（Additional information）

bun#44693 の一部として投稿した。投稿したのは英語版。

**依頼: コンソールのコードページを一切変えないでほしい。** 画面への出力は `WriteConsoleW`（UTF-8 → UTF-16）、パイプ・ファイルへはバイト列をそのまま、コンソールからの入力は `ReadConsoleW` で読む。どれもコードページに依存しない。node と deno は一度も変えず、下のすべてのケースで正しく出す。GitHub のコード検索では、リポジトリに `WriteConsoleW` の使用は見つからない。

控えて戻すやり方は安全にできない。1 つの窓で複数のプロセスが同じ共有の値を控えては戻すので、終わる順で何が残るかが決まる。強制終了では戻す処理そのものが走らない（ソースのコメントにも「強制終了されると戻らないことがある」と書かれている）。ソースへのリンクはいまの `main` を指す。

**測った害**（Windows 11 10.0.26300、conhost、開始のコードページ 932 と 437 の窓、bun 1.4.2 と canary。比べる相手は node v26.10.0 と deno 2.9.7。各プロセスが自分で `GetConsoleCP` / `GetConsoleOutputCP` を読み、画面は `ReadConsoleOutputCharacterW` で読み取った）。node と deno ではどれも起きず、順番を決めたケースの判定は 932 と 437 ですべて同じだった。

1. **パイプでつないだ相手の出力が化ける**（#43660 の症状）。bun 同士が直接つながっていなくても起きる（`bun | node | bun`）
2. **回ごとに結果が変わる。** #43660 のコマンドを毎回新しい窓で 10 回流すと、932 では 1.4.2 が 6 回、canary が 7 回、437 では 3 回と 9 回化けた。回数も流すたびに変わる。node と deno は毎回正しかった。起動・終了の順を決めると、どの順も 3 回中 3 回同じ結果になった
3. **窓に 65001 が残る。** 通常終了でも順番によって残り、強制終了（`taskkill /F`）でも残る
4. **65001 が残ると、同じ窓のほかのプログラムが壊れる。** `cmd.exe` が SJIS のバッチファイルの残りを読み違え（日本語の行が `�������` になる）、`chcp` や `pause` のメッセージが英語になる
5. **パイプのデータそのものは壊れない。** 害はすべて、共有されたコンソールの状態を変えることから起きている

bun#44693 への続報のコメント（PR #43662）

bun#44693 へのコメントとして投稿した。この Issue を出したとき、bun#43660 への Open の修正 PR #43662 を見落としていた。そのあと PR の版を同じ試験一式で測った。投稿したのは英語版。

続報: この Issue を出したとき、#43660 にすでに Open の修正 #43662 があることを見落としていた。その CI の Windows x64 のビルド（1.4.3-canary.1+576eb251a）を、同じ試験一式で、コードページ 932 と 437 で始めた窓で流した。

**#43662 で直るもの**（どちらのコードページでも全ケース）:

- `console.log` ／ `process.stdout` の出力は、どの起動・終了の順でも化けなくなった。#43660 のコマンド（20 回とも正しい。各コードページで 10 回）と `bun | node | bun` も含む。
- 起動・終了の順を決めた形では、通常終了のあとに 65001 が残らなくなった。

**#43662 のあとも残るもの:**

1. bun は起動時に窓を 65001 に切り替えたまま（入力と出力。プロセスの中から読んだ値）。bun が動いているあいだ、窓のほかのプロセスはすべて 65001 にさらされる。
2. 強制終了（`taskkill /F`）では 65001 が残り、そのあと同じ窓で流すバッチファイルは読み違えられる。
3. `fs.writeSync(1)` ・ `fs.write(1)` ・ `Bun.write(Bun.stdout)` は `WriteFile` のまま。送り手が先に終わる順では化ける（どの API も、932 と 437 で 3 回中 3 回）。PR の説明文とレビューにもそう書かれている。
4. 「自分が変えたコードページだけを戻す」でも、競合に負けることがある。#43660 のコマンドを 20 回流したうち 1 回、2 本とも終わったあと、入力側は 932 に戻ったのに、出力側は 65001 のまま残った。考えられる順: 送り手が 65001 にしたあとで受け手が出力側の値を控え、送り手が終わって 932 に戻し、そのあと受け手が 65001 にする。受け手は 65001 を控えているので、戻さない。

なので、ここでの依頼は変わらない。コンソールのコードページを一切変えず、画面への出力はすべて `WriteConsoleW` で書いてほしい。そうすれば控えて戻す処理は要らず、強制終了でも何も残らない。
